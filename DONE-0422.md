# DONE-0422: Freebuff as a free coder inside Meldmind

## What changed
- `server/freebuff-agent.js` (new). Pure functions on screen text: model pick rules (`modelDecision`, `isSafeModelText`, `statusShowsModel`), idle (`isIdle`), ad stripping (`stripAds`, `extractAd`), `cleanTranscript`, `answerFrom`, limit detection (`detectLimit`: concurrent session, daily hours at 0, session ended), sign-in (`detectSignIn`, https links only), masking (`prepareTask` runs `maskPrivate` then refuses anything that still looks like a key). A `Terminal` abstraction with two drivers: `tmuxDriver` (spawn with argument arrays, no shell strings; secret env vars are unset for the Freebuff process) and `ptyDriver` (dynamic import of `node-pty` only if already installed; nothing added to package.json). With no driver: "Freebuff needs the built-in terminal, which is not available on this computer yet." `createFreebuff` is the session manager (start, ask, stop, status; one request at a time; restarts when the folder changes). Hooks: `freebuffReady()`, `freebuffRun(task)`, `registerFreeBuffHooks(mod)`, and `freebuffStep(t)` for mission steps.
- Safety in code: never accepts a row with training, Space Bunny, a dollar price, upgrade, locked or "prompts kept"; the status bar must show the chosen model right before paste; the request is masked and refused if it still looks like a key.
- Sign-in: the link is surfaced as "Open this link to sign in to Freebuff (free)" (button in the page uses `ccDesktop.openExternal` or `window.open`). Nothing is stored or typed into the sign-in page.
- `server/plugins/freebuff.js` (new): GET /api/freebuff/status, POST /start, /ask { text, folder }, /stop. `makeRoutes(manager)` is exported for tests.
- Limits: `markTrouble("freebuff", ...)` with a plain reason (concurrent = "rate", daily/session = "credits"); cleared when it works again. `server/fallback.js`: two small edits so `markTrouble` accepts the id "freebuff" (it is not in the provider registry) and names it.
- `server/free-first-wire.js`: at the end, a dynamic `import("./free-bids.js")` then `registerFreeBuffHooks`; a missing file or missing `setFreeBuffHooks` does nothing. `server/free-bids.js` was not touched.
- `server/mission.js` (about 15 added lines, over the "few lines" ask): a code step uses Freebuff first when it is ready and the run is not private; if Freebuff fails or hits a limit the step is handed to the top-ranked AI and the reason is logged. Output is marked `free`.
- `web/features/freebuff.js` (new) and a row in `web/perf/registry.js`: "Free coder (Freebuff)" card in Settings: status chip, "Set up (one-time sign in)", sign-in button, read-only live window (polls /status every 2.5 s), "Sponsored (Freebuff)" line, "Ask the free coder" box, a "Free" chip on results. I did not add it to the Get free AIs dialog (free-ais.js) to keep that file alone.
- The 0.4.21 block was reversed on purpose (Chris, Oct 26): `server/savings.js` `isBlockedFree` now blocks only Space Bunny (the model that keeps prompts), not Freebuff. `server/plugins/providers.js` message is now "That model keeps your prompts, so Meldmind does not use it." `web/app.js`, `docs/USER-GUIDE.md`, `docs/help/getting-started.md` no longer say "Freebuff is not used". `test/savings.test.js` pins were rewritten to match (Freebuff allowed, Space Bunny refused and never ranked).
