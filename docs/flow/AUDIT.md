## 6. The 10 Riskiest Items

1. **Item 18 (12 Category Editors in Finish & Deploy - Size `L`)**
   - **Why risky**: Building or wiring 12 distinct domain editors (especially interactive Video sound/subtitle timelines, Music waveform editing, Presentations slide editing, Games level/item editing, and Cloudflare Pages deployment) can easily turn into 12 separate mini-apps.
   - **Mitigation**: Keep each finisher focused on high-value adjustments and export/publish actions, reuse existing modules (`artifacts.js`, `webbuilders.js`, `publish.js`, `builders.js`, `doc-export.js`, `schedules.js`, `remix-wfc.js`), and rely on `server/graduate.js` handoffs for heavy external DAWs/NLEs.
2. **Item 11 (Flow Mode 6-Stage Architecture, Sub-Projects & Live Horizontal Flowchart - Size `L`)**
   - **Why risky**: Touches core project data structures (`server/projects.js`), walkthrough/build-all state machines (`server/walkthroughs.js`, `server/build-all.js`), and top-of-screen chrome across Simple and Expert modes. Existing tests (`test/build-all.test.js`, `test/walkthrough-examples.test.js`) assert exact internal step IDs (`idea`, `questions`, `plan`, `build`, `test`/`review`, `done`).
   - **Mitigation**: Keep internal step IDs backward-compatible while aliasing/extending the 6 Flow stages and sub-project links.
3. **Item 17 & Item 27 (Local ONNX MiniLM Embeddings & Optional NVIDIA TensorRT Acceleration - Size `L` / `M`)**
   - **Why risky**: Native C++ bindings (`onnxruntime-node`, CUDA, TensorRT) and model weights (~50 to 150 MB) risk breaking Electron packaging (`electron-builder.yml`) or tripping `test/performance.test.js` (`server/perf/eager.js` forbids eager heavy imports and `server/perf/budget.js` caps installer growth at 15%).
   - **Mitigation**: Keep deterministic rules as Tier 1 on pure CPU, load ONNX/TensorRT lazily through `server/perf/addons.js` only on demand, and never bundle CUDA/TensorRT binaries in the base installer.
4. **Item 20 (Personas Menu, Community Persona Sections & Peer Review - Size `L`)**
   - **Why risky**: Requires a server/cloud backend (Supabase tables/RPCs), content moderation, and user-generated template sharing, raising legal/privacy and secret-leakage risks noted in `PLAN.md` Section 6.
   - **Mitigation**: Enforce template-only sharing through `server/redact-text.js` and `server/community-chat.js` (`SECRET` and `PROFANITY` filters), reuse HMAC signing from `server/marketplace.js`, and ship last in Phase C after legal sign-off.
5. **Item 21 (Browser Agents: 5 Specialized Roles, Verify Loop, Vision Fallback & Browser Sidebar Tools - Size `L`)**
   - **Why risky**: Coordinating 5 specialized agents (`Planner`, `Navigator`, `Researcher`, `Writer`, `Analyst`) with DOM + screenshot vision fallback inside `electron/browser-helper.cjs` can burn tokens rapidly or trigger false actions on complex shadow-DOM sites.
   - **Mitigation**: Keep `server/browser.js:295-352` (`assess` human approval gates on `login`, `pay`, `send`, `delete`, `submit`, `download`, `leave`), `MAX_STEPS = 16`, and the `$1` screenshot spend cap (`server/control-apps.js`) strictly enforced.
6. **Item 26 (Owner Mode Self-Chat, In-App Self-Building & Live Router/Momentum Overrides - Size `L`)**
   - **Why risky**: Allowing Meldmind to treat itself as a project and modify behavior/code from inside the app carries a high risk of breaking the running instance or accidentally exposing builder capabilities outside Owner Mode.
   - **Mitigation**: Gate every route strictly on `resolveTier() === "owner"` (`server/license.js:63`, which blocks `CC_DEV_OWNER` when `CC_PACKAGED === "1"`), run self-build edits in a git branch/worktree preview, and require explicit Owner approval before applying any change.
7. **Item 14 (Per-Project Media Folder, Asset Tray, Version Stacks & Cross-Project Links - Size `L`)**
   - **Why risky**: Media files currently split across `media.jobs.json` (`server/images.js` and `server/media-jobs.js` in `projects/<id>/media`) and `server/project-files.js` (`projects/<id>/files` + SQLite RAG index in `server/libraries.js`). Drag-and-drop across surfaces and version stacking can cause broken file references if paths are not unified.
   - **Mitigation**: Build a single project-media index layer over `projects/<id>/media` that stores stack lineage (`params.from`), tags, usage badges, and cross-project link pointers without moving or duplicating underlying files.
8. **Item 24 (Phone Companion Dual Control Queue & Live Sync - Size `M`)**
   - **Why risky**: Queuing new phone instructions while the desktop is actively streaming a mission or browser job (`S.live`) can cause state races between `server/mission.js`, `server/followup.js`, and WebSocket `agent.delta` events.
   - **Mitigation**: Queue phone intent packets on the server run object (`run.queuedDirections`) and consume them at safe step/turn boundaries with deterministic "latest explicit direction wins" ordering.
9. **Item 25 (Multi-AI Coordination: External Project Mirroring & Scheduled Task Takeover - Size `M`)**
   - **Why risky**: Third-party AIs (Claude, ChatGPT, Grok, Gemini) do not offer a standard API for reading or canceling their internal scheduled tasks or folders.
   - **Mitigation**: Scope project mirroring and task takeover to supported MCP/bridge endpoints (`server/meldmind-bridge.js`, `server/mcp.js`), exported history/config files (`server/history-import.js`), and explicit user-confirmed browser-helper actions.
10. **Slice A0-4b (Translucent Panes, Gradients & Rolling-Light CSS vs Contrast & GPU Performance Gates - Size `M`)**
    - **Why risky**: `backdrop-filter: blur(...)` and animated conic-gradient borders across multiple panes can drop frame rates on integrated GPUs or fail automated WCAG contrast checks (`test/field-contrast.test.js` enforces `>= 4.5:1` across all 6 themes).
    - **Mitigation**: Use CSS `@property` GPU-composited border masks (zero JS animation loops), cap simultaneous active rolling lights to at most 3, pause animations when `document.hidden` is true, fall back to solid tinted fills in `body.light-mode`, and run `node --test test/field-contrast.test.js test/themes.test.js test/a11y.test.js` after every style change.
